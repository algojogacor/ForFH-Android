# ForFH-Android V1.1 — 4 Fitur Baru, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rilis V1.1 (versionCode 2) dengan 4 fitur: (1) widget jadwal + alarm berikutnya, (2) halaman Jadwal di-upgrade (countdown + quick mute + info alarm berikutnya), (3) notif tugas pintar per deadline, (4) Info Kampus & rekap presensi.

**Architecture:** Tambahan modular di app yang ada. Widget via Glance (standalone, baca Room langsung). Halaman Jadwal: komponen baru di atas ViewModel baru. Deadline notif: planner murni baru + reuse alarm pipeline yang sudah teruji (guard/channel/skipDates). Info Kampus: pola client-DTO-Room-ViewModel-Screen yang sama dengan fitur sync yang ada (lihat SyncRepository & layar Tugas).

**Tech Stack:** Kotlin, Jetpack Compose M3, Room, Glance 1.1.x (androidx.glance:glance-appwidget), WorkManager, AlarmManager exact (sudah ada).

**Spec:** Fitur disetujui user 2026-08-16 (AskUserQuestion 4 opsi, semua dipilih). Konteks teknis & aturan alarm: `docs/superpowers/specs/2026-08-15-forfh-android-design.md` + `.superpowers/sdd/2026-08-15-forfh-android/progress.md`.

## TAMBAHAN FASE 6 (keputusan user 2026-08-16 malam) — UX latency-aware (server Koyeb Germany, RTT ~1.4 dtk)

### Task 10: Optimistic markDone + status sinkron per tugas
- **Tujuan**: tandai Selesai instan (tanpa nunggu PUT), dengan indikator status per tugas:
  PENDING (⏳ sync) / SUCCESS (✓ siap) / FAILED (⚠ retry — ketuk = kirim ulang).
- **Desain**:
  - `TaskEntity` + kolom `syncState` (PENDING/SYNCED/FAILED) + migrasi DB (Room version+1).
  - markDone: update Room + UI INSTAN (status DONE + syncState PENDING) → PUT background
    (viewModelScope) → sukses: SYNCED (tanpa sentuh UI lagi) / gagal: FAILED + pesan.
  - Pending list di DataStore (`pending_mark_done` stringSet taskId) → saat sync (replaceAll
    dari server) selesai: status PENDING diterapkan ulang ke lokal (server belum konfirmasi
    → jangan biar tertimpa "Belum"); yang SYNCED/FAILED ikut aturan server.
  - TDD: logika murni `applyPendingStatuses(tasks, pendingIds)` + DAO/migrasi test.
- **File**: `data/db/TaskEntity.kt`, `TasksDao.kt`, `AppDatabase.kt` (migrasi), `data/prefs/Preferences.kt`,
  `ui/tugas/TugasViewModel.kt`, `ui/tugas/TugasScreen.kt` (chip status + retry tap),
  `sync/SyncRepository.kt` (re-apply pending setelah replaceAll).
